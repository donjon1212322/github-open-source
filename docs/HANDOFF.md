# HANDOFF — как продолжить разработку

**Кому:** инженеру или модели, впервые открывшей этот репозиторий.
**Читать первым.** Здесь всё, что нужно, чтобы понять проект и не наступать
на грабли, которые уже учтены в коде.

---

## 1. Что это такое в одном абзаце

Автономная система, которая каждый день находит интересные open-source
проекты на GitHub, пишет про них посты и публикует в Telegram-канал.
Плюс статьи на Telegraph и dev.to, кросс-посты в Bluesky / Facebook,
ежедневный AI Brief по новостям и недельный дайджест с опросом. Ноль затрат
на инфраструктуру: всё работает на GitHub Actions, генерация — на бесплатном
тарифе Gemini.

---

## 2. Где мы находимся прямо сейчас

| | Состояние |
|---|---|
| Код | готов: 376 тестов, 68.60 % branch-inclusive coverage, 64/64 мутаций убито |
| История | чистый старт `2093a5a`; живой state вынесен в orphan-ветку `state`, в `main` только пустой bootstrap |
| Публикация | включена: `APP_ENV=production`, `PUBLISH_TARGET=main` |
| Режим | `main` требует `APP_ENV=production`, `PUBLISH_TARGET=main` и реального `TELEGRAM_MAIN_CHANNEL_ID` |
| GitHub Actions | CI и CodeQL активны; публикующие workflow включаются на этапе запуска |

Target lock — главное правило: пустой тестовый ID никогда не подменяется
основным каналом, а `main` недоступен без трёх переменных сразу.

## 3. Что нужно знать до первой строчки кода

Эти решения принял владелец. Они не обсуждаются и не «улучшаются» без него.
Полный список — [`OWNER_RULES.md`](OWNER_RULES.md), там же они зафиксированы
исполняемыми тестами.

| Правило | Почему именно так |
|---|---|
| 3 поста в день | Каденция владельца; четвёртый слот отклоняется до сетевого вызова |
| Английский язык, под Google | Единый голос и Discover-индексация |
| 1200×630 карточка | Замороженный редакционный дизайн |
| Только реальный канал в CTA | Приватные `t.me/c/` ссылки никогда не попадают в публичные посты |
| Facebook = make.com + Google Sheet | Никакого прямого Graph API, Page-токена и `FEATURE_FACEBOOK` |
| Секреты только в GitHub | Значения не читаются, не логируются, не коммитятся |

## 4. Команды

```bash
ghos-v6 doctor              # 13 проверок интеграций, ничего не меняет
ghos-v6 collect             # собрать кандидатов
ghos-v6 publish --slot X    # опубликовать один проект
ghos-v6 crossposts          # обработать очередь кросс-постов
ghos-v6 article             # статья дня
ghos-v6 article-update      # перерисовать уже опубликованную статью (PUT, без дубликата)
ghos-v6 news                # AI Brief
ghos-v6 digest              # воскресный топ-5 + опрос
ghos-v6 report              # недельный отчёт владельцу
ghos-v6 metrics             # просмотры постов
ghos-v6 poll-close          # закрыть опрос
ghos-v6 learn               # пересчитать модель ценности
ghos-v6 facebook-handoff    # строка в Google Sheet для make.com
ghos-v6 moderation          # удалить спам из обсуждений
ghos-v6 sources             # показать проверенные источники
ghos-v6 scheduled --schedule "10 7 * * *"   # маршрутизация по крону
```

Локально: `PYTHONPATH=src python3 -m ghos_v6.cli doctor`.

## 5. Как запустить

1. Записать 7 Secrets и 16 Variables — [`SECRETS_CHECKLIST.md`](SECRETS_CHECKLIST.md).
2. `ghos-v6 doctor` — убедиться, что 13/13 отвечают.
3. Включить `Doctor` и `Publishing pipeline`.
4. Один `publish`, визуальная проверка поста и статьи.
5. Проверить, что `commit-state` пишет в ветку `state`, а `main` остаётся
   пустым bootstrap; CI, CodeQL и `Doctor → State branch health` зелёные.

Порядок операций и откат — [`RUNBOOK.md`](RUNBOOK.md), ежедневная работа —
[`OPERATIONS.md`](OPERATIONS.md), устройство модулей —
[`ARCHITECTURE.md`](ARCHITECTURE.md), форматы постов —
[`CONTENT_FORMATS.md`](CONTENT_FORMATS.md).

## 6. Чего в этом репозитории нет

- Истории прежних публикаций, ID статей и постов, логов прогонов.
- Прямой публикации в Facebook Page; Page-токен и id страницы не нужны.
- Удалённой социальной сети: контур полностью вырезан из кода, конфигов,
  схемы Gemini, workflow и тестов.
- Личных Telegram-сессий, клик-трекинга и внешних редиректов.
