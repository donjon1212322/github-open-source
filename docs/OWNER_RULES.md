# Правила владельца

Каждое правило здесь — прямое указание владельца канала. Часть из них
родилась из отвергнутых вариантов: если что-то здесь помечено «отвергнуто»,
не предлагайте это снова.

---

## Формат публикаций

### Длинный текст, не фото
Пост идёт **текстовым сообщением** (лимит Bot API 4096 символов), а карточка
прикрепляется **сверху как большой превью-блок** через `link_preview`.
Фото-пост отвергнут: подпись к фото ограничена 1024 символами, и история
не помещается.

### Карточки
- Горизонтальные **1200×630**. Квадрат и портрет — отвергнуты внутри канала.
- Стиль **Editorial Daily** по умолчанию, **Neon Terminal** для CLI/TUI,
  **Glass Aurora** только для AI Brief, **Editorial Sunday** для дайджеста.
- «Обводка не нужна» — рамку вокруг карточки убрать.

### Копирайт
- **Не сухой.** Никаких пресс-релизов и канцелярита.
- **Не заканчивается на «...»**.
- **Заголовки не для разработчиков.** Обычный человек, листающий ленту,
  должен захотеть открыть. Не `jargon`.
- **Технические названия моделей сохраняются полностью**: вендор + точное
  имя продукта + версия. `GPT-6.2`, а не «новая модель OpenAI».
- **Заголовки и подводки разделяются по площадкам:**
  - Telegram и статья — любопытный неспециалист;
  - Bluesky — проще и короче;
  - Facebook — самый простой язык.

### Картинки
- **Всегда на ImgBB.** Владелец требует явно.
- Порядок выбора: картинка из README репозитория → наша карточка →
  GitHub OpenGraph.
- Картинка из README тоже **перезаливается на ImgBB**, чтобы пост не
  зависел от чужого хостинга.

## Отбор проектов

- **Интересные проекты, а не техническая библиотека.** Инструмент, приложение,
  игра, полезная утилита — да. `fast-json-parser` — нет.
- **Исключение:** агентские скиллы, Claude Code, MCP-серверы — это
  явно разрешено.
- **Telegram-источники должны постить каждый день.** Канал, который замолчал,
  из пула убирается.

## Площадки

### Telegram
- **3 поста в день.** Утро Европы, день Европы, пик США.
- Только **@open_source_friend** — канал владельца. Остальные Telegram-источники
  нашёл агент, они не принадлежат владельцу.

### Кросс-посты
- **Только лучший пост суток** уходит в Bluesky и Facebook.
  Не все три поста — один, по оценке.
- **Telegraph — на каждый пост**, без исключения.

### SEO
- **Английский язык, под Google.** Не русский, не два языка.
- dev.to и Telegraph **не должны конкурировать за один запрос**:
  у каждого свой `seo_query` и свой угол (`telegraph_angle`).

### Facebook
- Публикация **через make.com, читающий Google Sheet**. v6 не публикует
  в Page напрямую. Это архитектурное требование, не временное.

### Bluesky
- Подводка = первый пункт брифа. Раньше лид и первый буллет дублировались —
  исправлено.

## AI Brief (новостной формат)

- **Отдельный формат, отдельный слот.** Ежедневно 19:10 по Москве
  (16:10 UTC), после последнего поста проектов.
- **Может выйти без первоисточника.** Для запуска модели или продукта само
  видео является свидетельством запуска.
- **Но без пометки «подтверждения нет».** Владелец отверг эту формулировку.
- **Сплетни и «левые» видео — не выходят.** Обзоры и запуски — да.

## Технические ограничения

| Правило | Обоснование |
|---|---|
| **Ключи не трогать до продакшна** | «пусть лежат на своих местах до запуска проекта в продакшене» |
| **Никогда не печатать секреты** в чат и логи | — |
| **`publish_guard` отвергнут** | чёрные списки фраз дают ложные срабатывания на реальных репозиториях |
| **Тестовый канал 1:1 как продакшн** | никаких тестовых заглушек и пометок |
| **Никаких обёрток ссылок и трекинга** | владелец отверг |
| **Статический пул источников отвергнут** | нужен живой поиск |
| **«Делай столько запросов, сколько нужно, но учитывай лимиты — качество важнее»** | — |

## Про запуск и целевую блокировку

**Правила приняты владельцем 2026-11-03.** Публикация разрешена, включение
`Doctor` и `Publishing pipeline` допускается. Порядок запуска и чек-лист
приёмки — в [`RUNBOOK.md`](RUNBOOK.md).

Ограничения, которые сохраняются всегда:

- **Target lock не отключать**: `main` доступен только при одновременных
  `APP_ENV=production`, `PUBLISH_TARGET=main` и заданном
  `TELEGRAM_MAIN_CHANNEL_ID`. Пустой тестовый ID никогда не подставляется вместо
  основного канала.
- **Тестовый канал 1:1 как продакшн**: без заглушек и тестовых пометок.
- Значения ключей остаются в GitHub Secrets/Variables, никогда не в git и
  никогда не в логах.
- Переключение на боевой аккаунт/канал и остановка прежнего бота — отдельные
  решения владельца.

> **Неофициальный проект.** «GitHub Open Source» — название канала и
> аккаунтов, проект не связан с GitHub, Inc. и не имеет прав на бренд
> GitHub. При переезде на боевые аккаунты добавьте пометку
> «Unofficial · not affiliated with GitHub, Inc.» во все описания.

## Отвергнутые варианты — не предлагать снова

1. Отдельный вызов ИИ на каждую площадку (8–9 вызовов на пост) — вместо
   этого один общий бриф + вызов поверхностей.
2. Публикация фото-постом с подписью.
3. Квадратные и портретные карточки в канале.
4. Ссылки через редирект-обёртку.
5. Пометка «подтверждения нет» в брифе.
6. Чёрный список фраз (`publish_guard`).
7. hashnode как обязательная площадка.

## Решения владельца 11.11.2026 (после жалобы на опоздания в часы)

- **Внешний будильник — основной.** Worker `* * * * *` запускает команды
  через `workflow_dispatch` в нужную минуту; это проверено по логам Actions
  (start lag = 0). Запоздалый родной `schedule` GitHub **игнорируется**:
  если cron пришёл позже своего окна на 15 минут, команда НЕ выполняется,
  в state пишется `late_schedule_ignored`, владельцу уходит одно сообщение
  в сутки. Исключение осталось одно: `53 18 * * 4` (close+learn) — обе
  команды идемпотентны по ISO-неделе. 12.11 владелец велел починить и
  Facebook, поэтому `23 18 * * *` из исключений убран (см. ниже).
- **Почему это было важно.** 09.11 вечерние слоты отработали вовремя
  (`3578`, `3579`), а те же cron пришли повторно в 00:44 / 02:11 / 02:26 уже
  10.11 и опубликовали `3580`, `3581` и вторую статью. Они заняли дневной лимит публикаций
  и маркер «один бриф в UTC-сутки» следующего дня, поэтому
  вечерние слоты 10.11 честно вернули `slot_already_done` /
  `news_already_published`. Опоздание было не у поста, а у **дубликата
  будильника**, который съедал завтрашний день.
- **Бриф без свежих новостей не выходит, но молча не пропадает.**
  `duplicate_digest` / `not_a_digest` / `source_unavailable` /
  `gemini_ineligible` пишут маркер завершённого слота и одно личное
  сообщение владельцу; Watchdog больше не делает серию слепых ретраев.
- **0 corporate / IPO / S-1 / policy в брифе.** В промптах теперь прямо
  «ZERO such items», а статус `official_document` отсекается
  детерминированно. Конкретный инструмент/интеграция остаётся новостью.
- **Структура второй статьи:** как минимум два `###` H3 обязательны.
  Нормализатор больше не превращает `###` в `##` (в `5008047` было 11 H2 и
  0 H3 именно поэтому); если Gemini всё же не дал H3, два per-story H2
  понижаются до H3 структурно, без нового текста.
- **Явный rollback.** `FEATURE_TELEGRAM_DISCOVERY=true` заведена в repo
  Variables и продублирована в `.env.example`; `false` возвращает старый
  YouTube-путь без правки кода. Пустая переменная = default `True`.
- **Facebook:** `FEATURE_SHEETS_HANDOFF=true` **разрешён владельцем**
  («фейсбук включен, он работает нормально»). Запись «facebook-handoff не
  включать» отменена; Make/Sheet и webhook не менялись. 12.11 владелец
  отдельно велел починить и запуск: см. следующий раздел.

## Решения владельца 12.11.2026 («да сделай нужные правки включая фейсбук»)

- **Facebook остаётся ВКЛЮЧЁННЫМ**, но больше не зависит от пунктуальности
  родного GitHub cron. 11.11 `23 18 * * *` пришёл на 6,5 ч позже. Теперь у
  `facebook-handoff` есть ежедневный маркер в `last_runs` (идемпотентность
  по UTC-суткам), он добавлен в `watchdog.SLOTS` и запускается сторожем не
  позже 18:30Z; запоздалый `schedule` отклоняется общим guard. Make/Sheet,
  webhook, схема строк, секреты и флаг не менялись.
- **Снимок просмотров больше не теряется.** 11.11 due-диспатч `metrics` в
  20:23Z получил `startup_failure` — runner не выделился, маркера не было,
  догона не случилось. `metrics` теперь пишет маркер только после реального
  измерения и добавлен в `watchdog.SLOTS` (20:30Z): до трёх попыток, без
  слепой серии.
- **Статистика дедупа считает и вышедшие брифы.** Раньше счётчик
  писался только при пропущенном брифе, поэтому после `3587` с одним
  удалённым повтором отчёт всё ещё говорил «фильтр ни разу не сработал».
  Теперь строка появляется для каждого не-refresh запуска, а точные повторы
  не удваиваются.
- **Что НЕ менялось:** лимит публикаций, UTC-сутки, граница 03:00 Минск,
  cron-строки, живой Worker (передеплоя не было, нужен Cloudflare-токен),
  секреты, опросы и `MIN_SIGNAL_VOTES`, live-посты, state вручную.
  Гарантии 100 % по минутам по-прежнему нет: bounded best-effort, без SLA.
